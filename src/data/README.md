# Catalog and manifests

No dataset is bundled. Resolve D2 and D3 before choosing a source or schema.

The eventual data boundary needs to describe:

- Stable species and form identifiers, display names, types, and base stats/BST.
- 2D artwork and display-model references with source-game provenance.
- The project rule of using the Pokémon model from its first Switch appearance, plus documented form/missing-model exceptions.
- Badge and sprite catalogs where those features need shared identifiers.
- Source/version/attribution metadata and a repeatable update process.

Keep a trainer's personalized Pokémon appearance, such as Seiko's Chingling ribbon, separate from canonical species/form data. Choose actual field names and validation during the catalog issue; this note is not an implemented schema.
